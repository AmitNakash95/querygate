Portable change set

Export & import a bundle

A change set is a downloadable file carrying only the documents you changed plus a fingerprint of the base version — for moving a reviewed change between environments or recovering a lost draft. It is never a stored server-side draft; importing one validates it and fills the editors, then you stage it normally. A connections.yaml document may carry a literal credential, so it is never kept in browser storage.

Callable queries

Named, parameterized queries this principal can run.

Curated query templates are the finite set of pre-approved questions an agent may ask by name — filtered by per-connection visibility, the same boundary as schema and catalog, and requiring no special scope. A template is a stored StructuredQuery, never raw SQL, and runs through the same policy and guardrail checks as an ad-hoc query.

Author a template

Compose a query template into the draft change set

Connect with admin:config:write to author templates into the draft.

Build a named, parameterized StructuredQuery without hand-writing templates.yaml. The form composes a validated template and merges it into the local templates.yaml draft — then validate, stage, and activate it from Releases, the same shared-release path as any config change. Raw-YAML editing stays available there as the escape hatch.

Parameter slots

No parameters — a template can be a fixed query with no slots.

min/max apply to numeric slots; max length to string slots; allowed values are comma-separated. The full template is validated against the same model the loader uses before it enters the draft.

Operational trends

Rejection, queue, and cost-estimate trends at a glance.

Aggregated from this process's own metrics — which reason rejects the most, whether queue pressure is building, whether the cost-estimate gate is silently failing open. Requires the admin:observability:read scope. This is an honest current-process snapshot, not durable history: counters are cumulative since the process started and reset on restart, and under the default in-process backends they are per-replica. It carries only low-cardinality aggregates — never a query, value, or principal.

Behavioral anomalies

Unusual per-caller behavior on the audit stream.

Each principal's recent activity compared against its own preceding baseline, read from the persisted audit stream — a sudden volume spike, a jump in its rejection rate, or a connection it has never touched before, even among queries policy allowed. This is a read-only signal for a human to investigate: QueryGate never auto-throttles or blocks from it. Requires admin:observability:read. Needs the JSONL audit sink enabled; otherwise it reports as disabled.
